# Архитектура

## Схема

```text
┌──────────────────────┐        ┌──────────────────────┐        ┌──────────────────────┐
│   Vue 3 + Vite       │  HTTP  │   ASP.NET Core       │  SQL   │   PostgreSQL         │
│   порт 5173          │ ─────► │   порт 5000          │ ─────► │   порт 5432          │
│   рисует экраны      │        │   проверяет правила  │        │   хранит данные      │
│   шлёт запросы       │        │   отвечает кодами    │        │   обеспечивает связи │
└──────────────────────┘        └──────────────────────┘        └──────────────────────┘
```
## Три узла

### 1. Клиентская часть — Vue 3 + Vite (порт 5173)

Рисует экраны: список инцидентов, карточку, форму создания.
Отправляет HTTP-запросы на сервер. Не хранит правила и не ходит
в базу напрямую.

### 2. Проверка правил — ASP.NET Core (порт 5000)

Принимает запросы, проверяет правила: допустимые статусы,
обязательные поля, существование категории, пустой ответственный.
Отдаёт коды 200, 201, 400, 404. Обращается к базе за данными.

### 3. Хранение данных — PostgreSQL (порт 5432)

Хранит таблицы Incident, Category, Employee. Обеспечивает связи
через внешние ключи. Название категории хранится один раз (ЗНФ).

## Связи

- Vue → ASP.NET Core: клиент спрашивает сервер.
- ASP.NET Core → PostgreSQL: сервер читает и пишет в базу.
- Прямой связи «браузер → база» нет.

## Пример запроса

POST /api/incidents
{
  "title": "Утечка данных клиентов",
  "categoryId": 2,
  "description": "Обнаружена утечка через API",
  "probability": "High"
}

Ответ: 201 Created, сервер сам ставит id, number, status = New,
assigneeUserId = NULL.

## Почему браузер не пишет в PostgreSQL напрямую

Все правила и проверки живут на сервере. Если бы браузер писал
в базу напрямую, любой пользователь мог бы обойти правила:
поставить любой статус, удалить строку, испортить данные.
Сервер — единственная точка, где проверяются права и логика.
